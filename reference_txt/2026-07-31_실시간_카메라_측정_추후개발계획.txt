SS Optical Performance Tool - 실시간 카메라 측정 추후 개발 계획
작성일: 2026-07-31
상태: 실제 카메라 및 DLL 연동 전까지 보류

1. 목표
- 카메라의 실시간 영상을 프로그램 화면에 계속 표시한다.
- 사용자가 측정 버튼을 누르면 해당 시점의 원본 프레임을 고정한다.
- 고정된 프레임으로 선택한 측정 모드를 실행하고 결과를 표시한다.
- 실시간 재개 버튼을 누르면 결과 화면에서 다시 실시간 영상으로 돌아간다.

2. 지원할 측정 모드
- Slanted Edge MTF
- USAF 차트 MTF
- RI(Relative Illumination)
- Distortion

3. 프로그램 상태 흐름
DISCONNECTED
  -> 카메라 연결 안 됨

CONNECTED
  -> 카메라는 연결됐지만 영상 취득 전

LIVE
  -> 실시간 프레임 취득 및 화면 갱신

CAPTURED
  -> 측정 버튼을 누른 순간의 원본 프레임을 별도로 복사하고 화면 고정

ANALYZING
  -> 고정 프레임으로 선택한 측정 알고리즘 실행

RESULT
  -> 분석 결과와 오버레이 표시 및 저장 가능

LIVE
  -> 실시간 재개 버튼으로 복귀

4. 측정 버튼 동작
1) 가장 최근의 정상 카메라 원본 프레임을 확보한다.
2) 측정 프레임을 별도 메모리에 깊은 복사한다.
3) 화면 갱신 타이머 또는 표시 신호를 정지한다.
4) 측정 버튼과 모드 변경 등 중복 동작을 잠근다.
5) 고정 프레임을 기존 파일 기반 분석 함수에 전달한다.
6) 분석 결과와 측정 프레임 오버레이를 표시한다.
7) 결과 저장과 실시간 재개 버튼을 활성화한다.

5. 화면 정지와 카메라 연결
- 측정 시 화면 표시만 정지하고 카메라 연결은 유지하는 방식을 기본으로 한다.
- 카메라 스트림을 반드시 중단해야 하는 DLL이면 스트림 정지/재시작 방식을 사용한다.
- 화면이 정지된 동안 새 카메라 프레임이 측정 프레임을 덮어쓰면 안 된다.
- 표시용 축소 영상이 아니라 카메라 원본 해상도와 원본 bit depth 프레임을 분석한다.

6. 스레드 구성
- 카메라 취득 스레드: DLL에서 프레임을 받아 최신 프레임 버퍼를 갱신한다.
- UI 스레드: 최신 프레임을 화면에 표시하고 버튼 이벤트를 처리한다.
- 분석 작업 스레드: 고정된 프레임으로 MTF, RI 또는 Distortion을 계산한다.
- 분석 중에도 UI 창 이동, 취소 및 상태 표시가 응답하도록 한다.
- 카메라 콜백 함수 안에서 무거운 분석을 직접 실행하지 않는다.

7. 프레임 버퍼 안전 조건
- 최신 실시간 프레임과 측정용 고정 프레임을 별도 변수로 관리한다.
- 프레임 교환 시 mutex/lock 또는 thread-safe signal을 사용한다.
- 측정 프레임은 np.copy 또는 DLL 버퍼 복사로 소유권을 분리한다.
- 프레임 번호와 카메라 timestamp를 함께 기록한다.
- 손상 프레임, 불완전 프레임 및 timeout 프레임은 분석하지 않는다.

8. UI 예정 구성
- 카메라 연결/해제
- 실시간 시작
- 측정 및 화면 고정
- 실시간 재개
- 결과 저장
- 카메라 연결 상태
- 실시간 FPS
- 프레임 번호
- 분석 진행 상태
- 오류 및 timeout 상태

9. 결과 저장 시 포함할 정보
- 측정 일시
- 원본 프레임
- 결과 오버레이 이미지
- 선택한 측정 모드
- 측정 결과 및 PASS/FAIL/INVALID
- 카메라 모델과 S/N
- 렌즈 모델과 배율
- Pixel pitch 및 영상 해상도
- 노출시간, Gain 등 DLL에서 제공되는 카메라 설정
- 적용된 판정 기준
- optical_settings.json 설정 사본 또는 주요 값
- 카메라 frame number와 timestamp

10. 카메라 DLL 적용 구조
- 분석 알고리즘은 현재처럼 numpy 영상 배열을 입력받는 독립 구조를 유지한다.
- 카메라 전용 코드는 frame provider 계층으로 분리한다.
- 예상 인터페이스:
  connect()
  disconnect()
  start_stream()
  stop_stream()
  get_latest_frame()
  get_camera_info()
  get_capture_settings()
- DLL이 바뀌어도 frame provider만 교체하고 MTF/RI/Distortion 계산 코드는 재사용한다.
- 실제 함수명, callback 방식, pixel format 및 메모리 해제 규칙은 reference_dll 자료 확인 후 확정한다.

11. 실제 카메라 전 선행 검증
- 폴더의 이미지들을 일정 주기로 순환 표시하는 가상 카메라 모드를 만든다.
- 측정 버튼 클릭 시 현재 프레임이 정확히 고정되는지 확인한다.
- 고정 프레임과 화면 표시 프레임이 같은지 frame ID로 검증한다.
- 분석 중 UI 응답성과 중복 클릭 방지를 확인한다.
- 실시간 재개 후 프레임 갱신이 정상 복구되는지 확인한다.
- 여러 번 반복 측정해 메모리 증가와 스레드 누수가 없는지 확인한다.

12. 추후 개선 후보
- 버튼 클릭 직전 여러 프레임 중 가장 선명한 프레임 자동 선택
- N개 프레임 평균을 이용한 노이즈 감소 측정
- 흔들림이 큰 프레임 자동 제외
- 자동 노출 안정화 확인 후 측정
- 일정 시간 간격의 반복 자동 측정
- 연속 제품 검사 및 결과 이력 저장

13. 구현 전 확인이 필요한 카메라 항목
- DLL 32/64bit 및 Python 3.12 호환 여부
- 호출 규약과 제공 언어 인터페이스
- callback 또는 polling 방식
- 지원 pixel format과 bit depth
- 영상 buffer 소유권과 해제 책임
- 프레임 stride와 정렬 방식
- 카메라 연결 및 stream 중단 오류 처리
- 노출, Gain, Trigger 설정 방법
- hardware/software trigger 지원 여부

14. 현재 결정 사항
- 실제 카메라 연결은 당분간 진행하지 않는다.
- 현재 파일 기반 측정 기능과 알고리즘 검증을 우선한다.
- 실시간 적용 시 측정 버튼으로 화면을 고정하고 결과를 표시한다.
- 결과 확인 후 실시간 재개 버튼으로 다시 LIVE 상태로 전환한다.
- 이미지 및 검사 결과 저장 기능은 실시간 카메라 개발 단계에서 함께 연결한다.

15. 해상도 항목의 정의
- 광학 설정의 Width/Height 명칭은 "카메라 입력 해상도 Width/Height"로 사용한다.
- 카메라 입력 해상도는 실시간 카메라에서 기대하는 설정 해상도이다.
- 우측 영상 정보의 해상도는 현재 파일 또는 카메라가 실제 출력한 프레임 해상도이다.
- 파일 열기 모드에서는 두 해상도가 달라도 비교, 경고 또는 설정값 변경을 하지 않는다.
- 파일 분석은 항상 파일에서 읽은 실제 원본 해상도로 수행한다.
- 파일을 열어도 optical_settings.json의 카메라 입력 해상도를 덮어쓰지 않는다.
- 실시간 카메라 모드에서는 설정된 카메라 입력 해상도와 실제 출력 프레임 해상도를 비교한다.
- 두 값이 다르면 측정 전에 경고를 표시한다.
- 해상도 불일치 경고에는 설정값과 실제값을 모두 표시한다.
- 경고 후 측정을 차단할지 계속 허용할지는 실제 DLL 연동 시 검사 정책으로 확정한다.
