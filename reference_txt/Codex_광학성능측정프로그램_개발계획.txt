광학 성능 측정 프로그램 개발 계획
=================================

1. 개발 목적
------------

Windows 환경에서 카메라의 실시간 RAW16 영상을 수신하거나 저장된 TIFF/JPG 영상을 불러와 다음 광학 성능을 측정하는 프로그램을 개발한다.

- 해상력 및 공간주파수: lp/mm
- CTF 및 환산 MTF
- RI: Relative Illumination, 상대조도
- Distortion: 렌즈 왜곡
- 측정 기준 대비 PASS/FAIL 자동 판정
- 판정 영상 및 측정 데이터 저장


2. 개발 환경
------------

필수 조건

- 개발 도구: Visual Studio Code
- 개발 언어: Python
- 대상 운영체제: Windows 10/11
- Python 권장 버전: 3.11 또는 3.12, 64bit
- UI 프레임워크: PySide6
- 카메라 연결: 제공된 DLL 직접 호출
- C# 예제 프로그램은 DLL 사용 방법 분석 및 동작 확인용으로만 사용
- Visual Studio 프로젝트로 새 프로그램을 개발하지 않음

권장 Python 패키지

- PySide6
- NumPy
- OpenCV-Python
- SciPy
- tifffile
- Pillow
- pyqtgraph
- openpyxl
- reportlab 또는 동등 PDF 라이브러리

DLL이 Native DLL이면 Python 표준 라이브러리인 ctypes를 우선 사용한다.

DLL이 .NET Assembly이면 pythonnet 사용을 검토한다.

3.3 Python 연동 판단

Native DLL

C# 예제에서 DllImport 사용
→ ctypes 또는 cffi로 직접 호출

.NET DLL

C#에서 using SDKNamespace 후 클래스 생성
→ pythonnet으로 DLL 로드

C++ 클래스 DLL

C 함수가 Export되지 않고 C++ 클래스만 제공된다면 Python 직접 연결이 어려울 수 있다.
이 경우에만 별도의 소형 C/C++ Wrapper DLL을 검토한다.

5. 공통 영상 데이터 구조
------------------------

카메라 영상과 파일 영상을 같은 구조로 전달한다.

예시:

from dataclasses import dataclass
from datetime import datetime
import numpy as np

@dataclass
class ImageFrame:
    image: np.ndarray
    width: int
    height: int
    bit_depth: int
    source_type: str
    timestamp: datetime
    frame_number: int = 0
    source_path: str | None = None

내부 영상 형식

RAW16 및 TIFF16
- dtype: uint16
- shape: Height × Width

JPG
- dtype: uint8
- shape: Height × Width 또는 Height × Width × 3

JPG는 분석 전에 Gray8로 변환한다.

- 파일명

- Bit Depth

6.4 TIFF 파일 저장

실시간 카메라 영상 캡처 시 다음 형식으로 저장한다.

- 원본 RAW16 TIFF
- 무손실 저장
- 카메라 원본 픽셀값 유지
- 표시용 영상 보정값을 원본 TIFF에 적용하지 않음
- 판정 ROI 및 결과는 TIFF 원본 데이터와 별도 메타데이터로 저장

선택 저장:

- 원본 TIFF
- ROI가 표시된 판정용 TIFF
- 화면 확인용 JPG 또는 PNG
- 측정 결과 JSON


7. 해상도 설정
-------------

사용자가 영상의 수평·수직 해상도를 입력할 수 있도록 한다.

입력 항목

- Width
- Height

범위

- 최소 권장: 320×240
- 기본값: 640×480
- 최대 권장: 1920×1080, FHD
- DLL이 지원하는 실제 해상도 목록을 조회할 수 있다면 Dropdown으로 제공

검증 조건

- Width와 Height는 양의 정수
- 카메라가 지원하지 않는 해상도는 설정 불가
- 프레임 데이터 크기와 설정 해상도가 일치하는지 확인
- RAW16 예상 데이터 크기 검증

Expected Bytes = Width × Height × 2

해상도를 변경하면 ROI 좌표와 검사 설정을 재검증한다.

12. MTF/해상력 측정 기능
-----------------------

12.1 입력값

- 기준 lp/mm
- 목표 MTF %
- 주파수 허용오차 %
- 최소 검출 신뢰도
- 최소 검출 라인페어 수
- 프레임 평균 수
- ROI별 목표값
- 배율
- 픽셀 피치

12.2 출력값

- 측정 lp/mm
- 주파수 오차 %
- Raw Contrast
- CTF %
- 환산 MTF %
- 패턴 방향
- 패턴 각도
- 검출 라인페어 수
- 측정 신뢰도
- 프레임별 편차
- PASS/FAIL

12.3 처리 절차

1. ROI 추출
2. 이상치 및 Bad Pixel 보정
3. 배경 기울기 제거
4. 패턴 방향 자동 검출
5. 바에 수직인 프로파일 추출
6. 여러 프로파일 평균
7. FFT, 자기상관 또는 Peak 간격 분석
8. 공간주파수 계산
9. Bright/Dark 평균값 계산
10. CTF 계산
11. 설정 방식에 따라 MTF 환산
12. 기준값 비교
13. 신뢰도 검증
14. PASS/FAIL 판정

12.4 회전 차트 처리

- 차트의 화면상 회전각 자동 검출
- 영상을 실제 회전하지 않고 패턴에 수직인 방향으로 프로파일 추출
- 각도 신뢰도가 낮으면 판정 보류
- 차트 원근 기울기가 지나치면 경고 표시

12.5 CTF와 MTF 구분

USAF 또는 Bar Target은 직접적으로 CTF를 측정한다.

프로그램 표시 항목:

- Contrast
- CTF
- Converted MTF

사용한 CTF→MTF 환산 방식은 설정과 성적서에 기록한다.


13. 실시간 MTF 표시

- 최소/최대 MTF
- 표준편차
- 측정 신뢰도

- lp/mm 주파수 오차가 허용 범위 이내
- 신뢰도 기준 이상일 때만 최종 판정

15.5 설치오차 경고

다음 조건에서는 자동 판정하지 않고 경고한다.

- 차트 검출점 부족
- 차트가 영상 전체를 충분히 덮지 못함
- 차트가 크게 기울어짐
- 차트 평탄도 불량
- 검출점 순서 인식 실패
- 재투영 오차 초과


16. 기준값 및 판정 기능
----------------------

공통 판정 상태

- PASS
- FAIL
- INVALID
- NOT MEASURED

INVALID는 분석 실패 또는 측정 신뢰도 부족을 의미한다.

MTF 판정 예

주파수 오차 ≤ 허용값
AND
측정 MTF ≥ 기준 MTF
AND
검출 신뢰도 ≥ 기준
AND
측정 안정도 충족

RI 판정 예

최소 RI ≥ 기준
AND
코너 RI ≥ 기준
AND
상하/좌우 비대칭 ≤ 허용값

Distortion 판정 예

최대 절대 Distortion ≤ 기준
AND
평균 Distortion ≤ 기준
AND
검출점 수 ≥ 최소값
AND
재투영 오차 ≤ 기준

전체 판정

활성화된 검사 항목 및 ROI가 모두 PASS인 경우에만 전체 PASS로 한다.

Overall PASS =
모든 활성 ROI PASS
AND
모든 활성 검사 모드 PASS

25. Codex 작업 원칙
------------------

1. 한 번에 전체 프로그램을 작성하지 않는다.
2. DLL 연결 검증부터 단계별로 진행한다.
3. 각 단계마다 실행 가능한 코드를 유지한다.
4. UI와 알고리즘을 분리한다.
5. 카메라 SDK 종속 코드를 camera 폴더로 제한한다.
6. 카메라 없이도 개발할 수 있도록 MockCamera를 구현한다.
7. MTF, RI, Distortion 모듈을 독립적으로 구현한다.
8. 분석 함수는 UI에 종속되지 않도록 한다.
9. 각 알고리즘에 단위 테스트를 작성한다.
10. RAW16 원본 데이터는 절대 표시용 변환으로 변경하지 않는다.
11. 예외를 무시하지 않고 로그에 기록한다.
12. 함수 및 클래스에 Type Hint를 적용한다.
13. 주요 API에는 한국어 또는 영어 Docstring을 작성한다.
14. 설정과 결과는 JSON 직렬화 가능하게 설계한다.
15. 테스트 영상으로 결과 재현이 가능하도록 한다.


26. 초기 Codex 전달용 작업 지시문
-------------------------------

Windows용 광학 성능 측정 프로그램을 Python으로 개발한다.

개발 도구는 Visual Studio Code를 사용하고, UI는 PySide6로 구성한다.
기존 C# 카메라 예제는 새 프로그램에 사용하지 않고, 제공된 Camera DLL의
함수 호출 방법, 구조체, 콜백, 초기화 및 종료 순서를 분석하는 참고자료로만 사용한다.

우선 전체 프로그램을 작성하지 말고 다음 순서로 진행한다.

1. C# 예제에서 DLL 유형, DllImport, CallingConvention, 구조체, Callback,
   Camera Open/Close, Stream Start/Stop, Frame 수신 순서를 분석한다.
2. Python에서 DLL을 로드할 수 있는 최소 테스트 프로젝트를 작성한다.
3. Python과 DLL의 x86/x64 일치 여부와 의존 DLL을 검사한다.
4. 카메라 검색, 연결, 단일 RAW16 프레임 수신을 구현한다.
5. 수신 프레임을 uint16 NumPy 배열로 변환하고 TIFF로 무손실 저장한다.
6. 카메라가 없어도 UI와 알고리즘을 개발할 수 있도록 MockCamera를 구현한다.

최종 프로그램 기능은 다음과 같다.

- 카메라 실시간 RAW16 영상 수신 및 표시
- 단일 프레임 캡처 및 RAW16 TIFF 저장
- TIFF/JPG 영상 불러오기
- 해상도 Width/Height 입력 및 설정
- 기본 해상도 640×480
- 지원 범위 320급부터 FHD까지
- 픽셀 피치 입력
- ROI 최대 4개 생성, 이동, 크기 변경, 삭제
- ROI별 기준 lp/mm 및 MTF % 입력
- 실시간 측정 lp/mm 및 MTF % 표시
- 패턴 회전각 자동 검출
- MTF/CTF 자동 측정 및 PASS/FAIL
- RI 기준 입력, 측정, Heatmap, PASS/FAIL
- Distortion 차트 정보와 기준 입력, 측정, Vector Map, PASS/FAIL
- 검사 설정 JSON 저장 및 불러오기
- 판정 원본 RAW16 TIFF 보존
- ROI와 결과가 표시된 판정 이미지 별도 저장
- 결과 JSON, CSV/XLSX, PDF 성적서 저장
- PASS, FAIL, INVALID 상태 구분
- 프로그램 로그 및 오류 처리

프로젝트는 다음 계층을 분리한다.

- camera: DLL 및 카메라 제어
- imaging: RAW16/TIFF/JPG 및 표시 변환
- inspection: MTF, RI, Distortion
- ui: PySide6 화면 및 ROI
- reporting: 결과 저장 및 성적서
- tests: 단위 테스트

모든 분석 알고리즘은 카메라와 파일 입력을 동일한 NumPy 영상 데이터로
처리하도록 구현한다. UI 스레드에서 영상 분석을 수행하지 말고 Camera,
Analysis, Report Worker를 분리한다.

첫 작업에서는 C# 예제와 DLL을 분석한 결과를 문서화하고,
Python에서 DLL 로드 및 카메라 Open/Close 시험 코드만 작성한다.
확인되지 않은 DLL 함수명이나 구조체를 임의로 가정하지 말고,
C# 예제 또는 SDK 헤더에서 확인한 내용만 사용한다.


27. 최종 검토 결과
------------------

현재 요구사항으로 Python 단독 UI·분석 프로그램 개발 방향은 타당하다.

추가되어야 하는 핵심 항목:

- DLL 종류, x86/x64, 의존성 검증
- RAW16 원본과 표시영상 분리
- 카메라가 없어도 개발 가능한 Mock Camera
- MTF가 아닌 CTF 직접 측정값 구분
- 단일 프레임이 아닌 실시간 안정화 판정
- RI용 자동 Grid 분석
- Distortion 차트의 행/열 및 간격 입력
- PASS/FAIL 외 INVALID 상태
- 원본 TIFF와 판정 오버레이 파일 분리
- 검사 설정 및 알고리즘 버전 저장
- 로그와 예외 처리
- 단계별 단위 테스트
- 배포 PC에서 DLL 의존성 시험

가장 먼저 진행할 작업은 UI가 아니라 DLL 직접 연동 가능 여부 확인과 RAW16 한 프레임 수신이다.
이 단계가 성공하면 이후 PySide6 UI와 세 가지 분석 기능은 독립적으로 빠르게 개발할 수 있다.
